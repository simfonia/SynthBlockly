# 工作日誌 2026-01-29

## 今日達成重點
1. **語系命名一致性全面修復**：
   - 修正了積木外觀顯示 Key 而非文字的 Bug。
   - 將積木定義由命令式 `appendField(Blockly.Msg[...])` 全面重構為聲明式 `jsonInit({ "message0": "%{BKY_...}" })`，解決了異步載入語系時的時序競爭問題。
   - 補齊了 `zh-hant.js` 與 `en.js` 中缺失的效果器、取樣器、自訂波形及 UI 按鈕的 Key。
   - 確保了函式 (Procedures) 積木在自訂語系下也能正確顯示中文（修正 "with:" 顯示為英文的問題）。
2. **高品質鋼琴音源升級 (Multisampling)**：
   - 實作鋼琴多重採樣邏輯，配置 A1-A7, C1-C7, Ds1-Ds6, Fs1-Fs6 共 26 個取樣點。
   - 已驗證 `public/samples/piano/` 下的所有 `.mp3` 檔案齊全且命名正確。
   - 徹底解決了單一 C4 取樣導致的高低音失真問題。
3. **自訂取樣器功能增強**：
   - 升級 `InstrumentService.createCustomSampler`，支援透過 **JSON 檔案網址** 載入映射表。
   - 修改產生器以判斷輸入內容，若為網址則執行 `fetch` 抓取配置，方便維護大型取樣庫。
4. **文檔與規格同步**：
   - 更新 `public/docs/` 下的所有 HTML 說明文件，統一使用「過採樣 (Oversample)」、「重新採樣 (Resampling)」與「頻率倍率」等專業名詞。
   - 於 `custom_sampler_readme` 中新增 GitHub 資源連結與進階 JSON 樣板說明。
   - 建立 `log/spec.md` 規格書，作為與 #processing 專案互通的技術基準。
5. **README 與 UI 優化**：
   - 更新 `README.md` 加入 V2.1 架構說明與 GitHub Pages 網址。
   - 修正「選定目前發聲音源」積木顏色為紅色，與「演奏」分類保持一致。

## 關鍵技術異動
- `InstrumentService.js`: `createCustomSampler` 改為 `async`，鋼琴配置擴充至 26 個取樣點。
- `instruments_blocks.js` & `transport_blocks.js`: 關鍵積木改為 `jsonInit` 以支援延遲語系解析。
- `sampler_generators.js`: 支援判斷 JSON 字串或網址。
